# Protect the data at startup with a check, a copy and a daily backup

At startup Rust checks the database with `PRAGMA quick_check`, refuses a file with a newer schema version, and copies the file to `backups/tracker-pre-migration.bak` before it migrates. A daily `VACUUM INTO` copy goes in `backups/` and the last 7 stay. The pre-migration copy has its own name, so the 7-copy rule never deletes it. The app never repairs or deletes a bad file. Both recovery options rename it to `tracker-corrupt-<date>.db`. The app gets dates from SQLite (`date('now', 'localtime')`) and adds no date crate. We did not choose automatic repair, because it can destroy the data that is left. We did not choose a cloud backup, because v1 has no accounts. One known cost: after "Start empty", the daily copies of the empty database can push older good copies out of the 7.

Note (design system v2): Settings also has a Backups section with "Last backup", "Open folder" and "Restore …". Restore there copies the newest daily backup over the database and restarts the app. The startup screen keeps its own restore.
